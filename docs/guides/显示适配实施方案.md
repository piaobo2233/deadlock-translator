# 显示适配实施方案

更新日期：2026-10-20。状态：**方案已确定，代码尚未按本方案改造，公开 beta.1 的限制仍然存在。** 本文描述后续实施与验收，不是已支持功能清单。

## 目标和当前限制

目标覆盖 16:9、16:10、21:9，以及主屏／副屏、窗口／无边框运行。独占全屏单独验证，32:9 等其他比例先作为实验配置，通过校准获得使用路径，不提前声称全面兼容。

当前屏幕接收默认要求主屏接近 16:9、至少 1280×720；游戏客户区必须完整覆盖主屏。选择固定分辨率预设时还要求与主屏像素完全一致。这些检查会直接暂停识别。自动模式不只接受菜单列出的三个分辨率，但也会拦截 16:10、超宽屏等比例。

| 当前实现 | 直接移除检查仍会遇到的问题 |
| --- | --- |
| [region.py](../../app/recognition/region.py) 按主屏尺寸解析区域并要求游戏覆盖主屏 | 副屏、窗口位置和黑边没有进入采集几何 |
| [main.py](../../app/main.py) 的采集循环继续检查主屏尺寸 | 上游放行后，后续采样仍可能停止 |
| [ocr.py](../../app/recognition/ocr.py) 的字号、气泡尺寸及部分阈值按参考画面高度缩放 | 只改截图框，不能同时修正识别缩放 |
| [layout.py](../../app/presentation/layout.py) 与浮窗按主屏原点和边界处理坐标 | 副屏负坐标可能被拒绝或夹回主屏，译文显示错位 |
| [gui/region.py](../../gui/region.py) 的“测试识别”仍截取主屏并检查比例 | 测试与实际采集可能出现两套结果 |

建议采用“游戏客户区定位 → 有效画面校准 → 聊天区域识别 → 局部坐标布局 → 桌面坐标显示”的统一链路。对未知比例提供校准入口；仅在无法安全取得画面时停止，并明确显示原因。

## 必须保持的行为

- 游戏不在前台、已最小化或客户区为空时停止新采集。保留暂停和退出行为。
- 保留现有 OCR 正文复核、多帧确认、超时、防重复请求及翻译链；显示适配不能顺便放宽这些条件。
- 不回退为整个桌面的无差别 OCR；校准只作用于所选游戏窗口。
- 不修改个人词库、记忆或请求记录格式；不自动调整 Windows 或游戏的分辨率。
- “没有聊天文字”“画面无法采集”“前台查询失败”“译文没有显示”分别诊断，不能统一描述为不支持分辨率。

## 统一坐标契约

实现一个供生产采集、测试识别和显示共用的轻量几何快照，可放在现有 `app/recognition/region.py`。不增加外部依赖。

| 字段 | 含义 |
| --- | --- |
| `hwnd` | 当前所选游戏窗口 |
| `client_rect_desktop` | 客户区在虚拟桌面的物理像素边界，允许非零及负坐标 |
| `viewport_rect_client` | 客户区内真正的游戏画面，扣除已校准黑边 |
| `viewport_size` | 有效游戏画面尺寸，作为 OCR 的参考尺寸 |
| `roi_local` | 有效游戏画面内的聊天搜索区域 |
| `revision` | 窗口、位置、DPI、有效画面或搜索区域变化时更新的标记 |

明确分开三层区域：窗口客户区、有效游戏画面 viewport、聊天 ROI。仅框选聊天范围，不能修正黑边造成的字号／气泡缩放错误。

识别和追踪在 ROI 局部坐标内计算。统一转换为：

```text
ROI 桌面原点 = 客户区桌面原点 + 有效画面客户区原点 + 聊天区域有效画面原点
气泡桌面坐标 = 气泡 ROI 局部坐标 + ROI 桌面原点
```

识别阈值的参考尺寸必须来自有效画面，不能用主屏尺寸，也不能把裁剪后的小图尺寸当成完整画面。复用 [tracking.py](../../app/recognition/tracking.py) 和 [visual_pulse.py](../../app/runtime/visual_pulse.py) 已有 origin 转换点，保证只平移一次。浮窗排除区域使用桌面物理坐标，在掩码边界转换回同一个 ROI 局部坐标。

字幕布局继续使用以 `(0,0)` 为原点的游戏局部坐标，不把副屏桌面坐标直接交给布局函数。浮窗定位时再转换到桌面坐标；负坐标不得直接沿用未经验证的 Tk `+x+y` 拼接，优先用明确支持有符号物理坐标的 Win32 定位方式，同时保留不抢焦点和鼠标穿透。

## 分阶段实施

### P0：明确状态与诊断

涉及：`app/recognition/region.py`、`app/main.py`、`gui/feedback.py`、`gui/game_settings.py`。

1. 让前台查询区分“其他窗口”和“API 查询失败”，记录固定错误分类／错误码，不记录其他应用路径或标题。
2. 运行状态增加采集几何、当前比例、DPI 和几何阻断原因；反馈导出保持字段白名单。
3. 设置页显示当前游戏画面、采集范围及实际阻断原因。未验证的比例标为“需要校准／实验适配”，不能用一个主屏比例判断替代所有状态。

验收：只显示游戏画面且无人聊天时也能验证采集几何；没有 OCR 计数增长不被误报为故障；默认报告不含密钥、原文、截图或个人文件路径。

### P1：打通客户区采集、局部布局和人工校准

涉及：`app/recognition/region.py`、`app/main.py`、`app/recognition/tracking.py`、`app/runtime/visual_pulse.py`、`app/presentation/layout.py`、`gui/region.py`、`gui/game_settings.py` 及配置校验。

1. 读取游戏客户区及桌面原点，截图使用对应桌面物理坐标。副屏采集启用适当的多屏截图方式；明确处理负坐标，不继续使用主屏尺寸检查作为采集有效条件。
2. 无黑边时默认有效画面等于客户区。提供一次性校准：必要时先框出有效游戏画面，再选择聊天搜索范围；普通用户优先走自动流程。
3. 新校准字段单独校验并兼容缺失值；不能只写旧 `capture_region`，因为现有 `capture_preset` 会优先覆盖旧选区。旧预设保留为兼容输入，但不再作为禁止其他比例的白名单。
4. 生产采集和“测试识别”共用几何快照；预览用真实有效画面及同一搜索区域，不再固定截主屏。
5. 浮窗按游戏局部边界布局，在显示边界转换到桌面坐标。覆盖主屏、左右／上方副屏及跨屏窗口位置。
6. 窗口同尺寸移动也更新 `revision`。几何变化时关闭旧帧源、撤销旧译文，丢弃旧几何下迟到的识别／翻译显示结果，然后恢复采集。
7. 静态位置名单等依赖裁图局部位置的缓存，在几何不匹配时停用；不为保留旧坐标而误过滤新区域，也不改用户数据格式。

验收：窗口移动、调整大小、分辨率变化和 DPI 跨屏变化后，识别及译文位置仍一致；无法沿用校准时给出重新校准提示。未知比例可进入人工校准，不因长宽比直接停用。黑帧／空客户区仍安全停止。

### P2：逐比例验证自动聊天区域

涉及：`app/recognition/ocr.py`、`app/recognition/region.py` 和真实截图／回放夹具。

1. 采集 16:10 和 21:9 的真实游戏画面，覆盖左右最外侧头像、短句、长句及堆叠气泡。
2. 根据素材确定 HUD 如何定位，再选择横向按宽度、按高度居中或实测模板。不能预设所有 HUD 都随宽度等比拉伸，也不能把拉伸一张 16:9 截图当作超宽屏适配证据。
3. 先修坐标适配，避免调整已有正文／垃圾过滤阈值；若素材证明阈值存在独立问题，另立可复现修复。
4. 自动定位失败时回到已保存校准。自动黑边检测可后续增加，不作为 P1 的前置依赖。

验收：每种新比例分别核对自动搜索区域与已标注正文，记录漏检和误检；没有真实样本或未通过的配置继续标为实验项。

### P3：回归、候选包与公开状态更新

涉及：相关测试、`docs/TESTING.md`、使用指南及后续 Beta 说明。

1. 将现有“超宽屏／副屏／窗口必须拒绝”的测试改为新的有效几何契约；保留真正不可采集情况的拒绝测试。
2. 运行相关几何、追踪、原图复核和字幕呈现测试，再执行项目完整隔离检查。测试使用假数据／网络拒绝，不复制真实配置或 Key。
3. 构建独立 Beta 候选，验证实际冻结程序，不覆盖 beta.1 附件。
4. 通过的配置列为已验证，未完成项继续明确标注；文档更新不等于已发布新程序。安装器问题保持独立处理，不把本机安装故障与显示适配混为同一缺陷。

## 验收矩阵

这些是最低覆盖维度，按下表代表配置组合执行，不要求盲目穷举全部笛卡尔积；跨屏负原点、混合 DPI 和几何变化须有确定的组合用例。

| 维度 | 最低覆盖 |
| --- | --- |
| 16:9 基线 | 1280×720、1920×1080、2560×1440、3840×2160 |
| 新比例 | 1920×1200、2560×1600、3440×1440；32:9 单列实验项 |
| 显示位置 | 主屏、右侧副屏、左侧负 X、上方负 Y |
| 缩放 | 100%、125%、150%，以及混合 DPI 跨屏移动 |
| 窗口模式 | 无边框、带边框窗口；独占全屏单列实机验收 |
| 几何变化 | 同尺寸移动、调窗口大小、最大化／恢复、切换分辨率 |
| 有效画面 | 无黑边、左右黑边、上下黑边、校准后尺寸变化 |
| 内容 | 无聊天、左右边缘消息、短句、六行长句、堆叠气泡 |
| 一致性 | Alt-Tab、最小化、黑帧、旧帧丢弃、迟到结果、排除区域只平移一次 |

自动化至少覆盖坐标往返、负原点、同尺寸移动失效、旧结果撤销及布局边界。可复用 [test_region_interaction.py](../../tests/test_region_interaction.py)、[test_visual_pulse.py](../../tests/test_visual_pulse.py)、[test_ocr_body.py](../../tests/test_ocr_body.py) 和 [test_match_translation.py](../../tests/test_match_translation.py)。

未来代码改造后的验证入口示例（本次文档交付没有执行应用回归）：

```powershell
python -X utf8 -m unittest discover -s tests -p test_region_interaction.py -v
python -X utf8 -m unittest discover -s tests -p test_visual_pulse.py -v
python -X utf8 -m unittest discover -s tests -p test_ocr_body.py -v
python -X utf8 -m unittest discover -s tests -p test_match_translation.py -v
python -X utf8 scripts/check.py
```

真实素材与完整对局验收需要分别记录配置、期望消息数、确认数、漏识别、误识别、译文绘制及耗时，不用合并平均值掩盖某一配置失效。合成坐标测试、缩放后的截图和单帧“测试识别”均不能替代新显示配置的实机验收。

## 发布门槛与回退

- 只有对应代码、自动化、冻结包和实际显示配置验收完成后，才能把该配置写为已支持。
- 现有 16:9 基线不能因适配改造退化；未知比例和独占全屏按实际结果标注。
- 新几何失效时停止旧帧及旧译文，提示恢复或重新校准，不回退抓取整个桌面。
- 保留旧公开包和旧配置读取能力；校准数据不可用时恢复自动定位并提示，不清除个人翻译资产。

当前进度：本次仅提交修改建议、实施步骤与验收标准。**尚未解除 beta.1 限制，也尚未发布显示适配修复包。**
