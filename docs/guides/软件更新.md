# 软件更新

在「设置 → 软件更新」查看当前版本、检查更新和阅读新版本概述。主面板发现新版本后显示入口，不在对局中自动弹窗，也不强制安装；修复版同样可以选择立即更新、稍后提醒或跳过。跳过后仍可手动检查。

只检查本项目 GitHub 的公开稳定 Release，不推荐测试版。启动后在后台检查，持续运行时每天检查；收起到托盘后仍可检查，下次打开主面板查看结果。后台网络错误保持安静；手动检查或下载失败会说明原因，可重试或打开官方下载页。不使用第三方镜像。严格离线运行、模拟和回放不会启动助手后台联网检查；严格离线助手打开的主面板也停止检查。

## 安装版一键更新

1. 保存尚未保存的编辑，再点击「下载并重启更新」。
2. 从官方 Release 下载完整安装包并校验 SHA-256；下载期间可继续使用。小修复也使用完整包。
3. 校验通过后请求安全退出，等待识别、请求和保存完成。不会强行结束助手；未能退出则取消本次安装。
4. 在本机保留旧程序副本和关键数据备份，再执行当前用户覆盖安装。
5. 安装成功后重新打开设置页，显示结果；按需在接收页启动翻译。

下载、校验或备份失败均不覆盖旧程序。安装失败时尝试恢复旧程序文件，**不自动回退个人数据或付费请求台账**，避免重复请求。若程序文件被手动改动或清单损坏，自动更新会停止，应使用官方下载页修复安装。

工作记录、旧程序、安装日志及数据备份保留在 `<程序目录>/backups/updates/<任务编号>/`。它们包含个人配置与密钥，仅用于本机恢复，**不要上传或分享**。安装失败的程序目录也保留供排错，不自动删除旧备份。缓存和结果回执在 `.temp/updates/`；更新偏好在 `data/updates.json`。

若自动恢复也失败，请退出所有锁语进程，保留 `data` 与上述备份，从官方下载页重新运行安装包。不要直接用旧备份覆盖请求台账；需要恢复数据时先保留当前数据，再使用现有备份恢复入口核查。

## 便携版、源码版与旧用户

便携版和源码版提供更新概述与官方下载页，首版不自动替换它们的程序文件。手动升级前退出旧助手并备份自己的 `data`；源码更新也应保留该目录。首次从旧便携包改装到安装版时，按[安装与首次使用](安装与首次使用.md)迁移个人资料，勿把整个旧程序目录覆盖到新安装目录。

test.3 及更早版本没有此更新检查功能，须手动升级一次，之后才可收到提示。

## 维护者发布要求

稳定版使用 `v1.0.0`、`v1.0.1` 这类标签，Release 不能标为 draft 或 prerelease。正文写本版概述、修复和注意事项。附件命名为 `LockLingo-<版本>-setup.exe`，并附同名 `.sha256` 文件，校验文件格式为 `SHA256  安装包文件名`。同时支持 GitHub 资产自带的 `sha256:` 摘要；程序只接受本仓库对应标签下的附件。

发布前验证源码版本、安装包内版本、附件名称和更新说明一致，并实际验证新装、覆盖升级、数据保留及失败恢复。候选源码有更新功能，不表示正式发行包已完成验收。
