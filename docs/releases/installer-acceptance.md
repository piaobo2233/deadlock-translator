# Windows 安装包验收

每个候选包单独记录。先用干净的 Windows 11 x64 桌面快照，再用 Windows 10 x64 复验。用普通测试账户、虚构数据和独立安装目录，翻译联网保持关闭。每个卸载入口从快照独立开始。

## 候选身份

从公开仓库选定标签或提交，运行 Actions 中的 **Build Windows release candidate**。下载产物，记录工作流链接、源码提交、`candidate.json`、候选 EXE 和 ZIP 的 SHA-256，以及上一正式版的标签和 EXE 摘要。用 `Get-FileHash <文件> -Algorithm SHA256` 核对本地字节。应用内更新使用正式通道或隔离测试通道分发同一候选包，记录实际解析的附件名和摘要，分别记录各通道的结果。

## 桌面验收

| 步骤 | 操作与通过条件 |
| --- | --- |
| 新装 | 交互安装候选包，勾选创建桌面快捷方式。应用列表显示版本，开始菜单和桌面入口指向本安装。打开首次设置，跳过密钥和校准，进入首页。 |
| 应用内更新 | 从快照安装上一稳定版，写入仅含测试值的配置和词库并保存摘要。从「设置 → 软件更新」检查、下载、校验、安装、重开。确认候选版本、两份资料摘要、应用登记的安装路径。 |
| 回退 | 更新后从「设置 → 软件更新」发起回退。记录起止版本和重开结果，核对回退前后的夹具资料摘要。 |
| 应用内卸载并保留 | 从「设置 → 卸载 → 卸载锁语」确认，卸载器询问是否保留资料时选「是」。核对程序、卸载登记、快捷方式、联动和旧自启、运行缓存和程序回退文件已清除。核对资料和个人备份，原目录重装后读回。 |
| 应用内彻底卸载 | 从快照安装后放入虚构配置、词库、个人备份、识别留档及可清理的运行残留，登记测试自启项。在安装目录的同级放一个无关文件。从应用内发起卸载并选择「否」，核对本安装文件、登记、快捷方式及自启均清除，同级文件摘要相同。 |
| Windows 应用列表彻底卸载 | 从另一干净快照重复彻底卸载检查，在 Windows 设置的应用列表发起。 |

记录 Windows 版本和内部版本号、架构、账户权限、安装路径、每项通过/失败/未运行，以及关联日志、脱敏截图和夹具摘要。资料丢失、应用内卸载失败或彻底卸载留下已知的本安装残留时停止放行。

## 可重复的静默冒烟

在同样的独立测试环境，可以先运行静默首装、覆盖升级、保留卸载、重装和彻底卸载脚本。脚本直接调用卸载程序。应用内入口、Windows 应用列表入口、首次设置和回退需按上表另验。

```powershell
python -X utf8 verify/uninstall_smoke.py <上一版EXE> <候选EXE> `
  --previous-version <上一版> --candidate-version <候选版> `
  --previous-sha256 <上一版SHA256> --candidate-sha256 <候选SHA256>
```

脚本写入 `.temp/uninstall-accept-*/report.json` 及各步骤日志。失败时保留该快照与报告，先处理原因再从干净快照重试。

## 放行和归档

1. 确认发行标签指向 `candidate.json` 中的 `source_commit`。将候选 EXE 与 ZIP 连同原校验文件上传到发行草稿，下载附件到独立目录执行 `python scripts/candidate_manifest.py verify <candidate.json> <附件目录>`。任一摘要不同，回到验收步骤。
2. 发行说明附源码标签、候选清单及对应的验收记录。长期保留这些证据，便于工作流产物过期后追溯。按发行要求一并附上第三方源码材料。
3. 草稿附件核对并放行后，从上一稳定版复核正式更新通道的发现、附件名、大小和摘要。更新命中异常时记录版本、通道和失败位置，按发行流程处理。
